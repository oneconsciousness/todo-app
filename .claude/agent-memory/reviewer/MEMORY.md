# Reviewer memory: todo-app

- **Run hooks and their tests under the macOS system Python too.** Use /usr/bin/python3 (3.9.6) as well as pyenv's 3.13. The hook tests spawn hooks with sys.executable, so run the suite with that interpreter, not just a 3.9 PATH. PEP 604 annotations once crashed every hook on 3.9, and a crashed hook let the command through.
- **The Bash guards use denylists of program names, and that is where they leak.** Probe wrappers (env, sh -c, sudo -u, command -p, a brace group, then/do, backticks), long-option abbreviations (BSD and GNU grep accept --recur, git accepts --no-verif and --no-inde), sequence braces (.e{m..o}v) and zsh glob groups. Probe the allow-listed commands in settings.json first (grep, find, git diff), because a bypass there runs with no prompt.
- **Secret-name patterns feed three places: the hook, the settings deny list and .gitignore.** A pattern that is too broad hides source files such as credentials.py from git as well as from the agent. Check all three together.
- **The live hooks in a review session parse heredoc bodies as shell.** Write probe payloads to files with placeholders for env names, key names, brace lists and reader programs. Keep separators out of the text. To push in scratch repos, seed a bare remote with fetch.
- **Tests that write several files into one temp repo per test cannot fail on later subtests.** An earlier file's hit satisfies every later assertion. Mutation-test helper-based suites such as scripts/tests/test_check_hygiene.py by breaking one check and rerunning.
- **Audit each allow-listed command for a flag that widens its reach:** git `--no-index` on directories, ruff `--config extend-include`, kubectl `-o yaml` on Secrets, git `--output`. These ran with no prompt until the S1 final pass.
- **Re-read the settings.json allow list before writing probes.** It is the attack surface: a bypass there runs with nobody asked.
- **Branch protection must read the branch where the command runs, not the session cwd.** It now follows `cd` and `git -C` (fixed after the S1 re-review, with a worktree test). .claude/worktrees/ exists, so keep probing worktree paths whenever the guard changes.
- **Mutation-test every security property by deleting the line that guards it, then rerun the suite.** A property with no failing test is untested, however obvious it looks. In Cf, deleting sign-in's dummy password check (equal timing for unknown emails) left the suite green, as did comparing emails as plain text instead of citext. Do this for timing equalisers, ownership filters, origin checks and unique-index handling.
- **Starlette's 500 handler runs outside every user middleware.** A handler registered for `Exception` runs in `ServerErrorMiddleware`, so its response skips the request-id and header middleware, and the exception is re-raised for the server to log a second time. Check that a 500 carries the same headers as any response and that its traceback is logged exactly once.
