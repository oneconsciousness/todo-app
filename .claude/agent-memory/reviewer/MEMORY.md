# Reviewer memory: todo-app

- **Run hooks and their tests under the macOS system Python too.** Use /usr/bin/python3 (3.9.6) as well as pyenv's 3.13. The hook tests spawn hooks with sys.executable, so run the suite with that interpreter, not just a 3.9 PATH. PEP 604 annotations once crashed every hook on 3.9, and a crashed hook let the command through.
- **The Bash guards use denylists of program names, and that is where they leak.** Probe wrappers (env, sh -c, sudo -u, command -p, a brace group, then/do, backticks), long-option abbreviations (BSD and GNU grep accept --recur, git accepts --no-verif and --no-inde), sequence braces (.e{m..o}v) and zsh glob groups. Probe the allow-listed commands in settings.json first (grep, find, git diff), because a bypass there runs with no prompt.
- **Secret-name patterns feed three places: the hook, the settings deny list and .gitignore.** A pattern that is too broad hides source files such as credentials.py from git as well as from the agent. Check all three together.
- **The live hooks in a review session parse heredoc bodies as shell.** Write probe payloads to files with placeholders for env names, key names, brace lists and reader programs. Keep separators out of the text. To push in scratch repos, seed a bare remote with fetch.
- **Tests that write several files into one temp repo per test cannot fail on later subtests.** An earlier file's hit satisfies every later assertion. Mutation-test helper-based suites such as scripts/tests/test_check_hygiene.py by breaking one check and rerunning.
- **Audit each allow-listed command for a flag that widens its reach:** git `--no-index` on directories, ruff `--config extend-include`, kubectl `-o yaml` on Secrets, git `--output`. These ran with no prompt until the S1 final pass.
- **Re-read the settings.json allow list before writing probes.** It is the attack surface: a bypass there runs with nobody asked.
- **Branch protection must read the branch where the command runs, not the session cwd.** It now follows `cd` and `git -C` (fixed after the S1 re-review, with a worktree test). .claude/worktrees/ exists, so keep probing worktree paths whenever the guard changes.
- **Mutation-test every security property by deleting the line that guards it, then rerun the suite.** A property with no failing test is untested, however obvious it looks. In Cf, deleting sign-in's dummy password check (equal timing for unknown emails) left the suite green, as did comparing emails as plain text instead of citext. Do this for timing equalisers, ownership filters, origin checks and unique-index handling.
- **Starlette's 500 handler runs outside every user middleware.** A handler registered for `Exception` runs in `ServerErrorMiddleware`, so its response skips the request-id and header middleware, and the exception is re-raised for the server to log a second time. Check that a 500 carries the same headers as any response and that its traceback is logged exactly once.
- **Frontend optimistic rollbacks run after the global 401 handler.** MutationCache.onError (clear + go to sign-in) fires before each hook's own onError, so a restore re-creates cleared list queries for the next user. Probe every new rollback path with a 401.
- **TanStack scoped mutations run onMutate at once; only mutationFn queues.** Snapshots therefore stack, and any other mutation's unconditional `invalidateQueries(lists)` refetches between queued moves. A focus refetch waits for paused scoped mutations (resumePausedMutations), so test with a toggle, not focus.
- **`throwOnError: true` also throws on background refetch errors when data is cached.** Check every query that sits under a draft or form for this.
- **Mutation-test the frontend race tests in a scratch `git worktree` with node_modules copied in.** In D, removing cancelQueries, the move isMutating gate, or the delete rollback left every test green.
- **Path guards on `returnTo` need to reject tab, CR and LF.** The URL parser strips them, so `/\t/evil.com` resolves to evil.com. React Router's history.push falls back to `location.assign` when pushState throws; replace does not.
- Check each commit is green without touching the worktree. Run `git archive <sha> backend | tar -x -C <scratch>/<sha>`, then run pytest from the extracted backend dir with the worktree's own virtualenv python (python -m pytest). There is no editable install, so `app` imports from the copy. The same copy is the place for guard-removal mutation tests. A safety check blocks rm -rf on a shell variable, so use a fresh directory per run.
- Mutation-test every WHERE filter in app/db/tasks.py. In the api-tasks review, the neighbour reads' `Task.id != excluding` filters could be removed with every test still green. Integration tests here cover status codes well, but filters that only keep ranks stable go untested.
- A regex check on a numeric header followed by int() gives a 500 on 4,301 or more digits. Python's int-to-string digit limit raises ValueError (the If-Match parser hit this). Bound the digit count inside the regex.
- Sync def dependencies run on the thread pool; the traceback shows run_in_threadpool. Base get_settings and get_hasher set this precedent, and new pure dependencies such as expected_version copy it. Flag it as low and point to the base precedent.
- Optional but not nullable request fields use `X | None` plus a before-validator that refuses null. OpenAPI then still advertises null. Check the JSON schema when frontend Zod schemas are hand-mirrored from it.
- The author tends to parametrise a pure rule's cases at the integration layer (seven If-Match cases, each signing up a user). testing.md and plan section 6.3 want the cases in unit tests and one case for the wiring.
- The Bash guard hook trips on markdown bold that ends in a period (it reads the period and asterisks as an env-file glob). Write memory entries without bold.
- To hide null from a field's published schema, use `Annotated[X | None, WithJsonSchema(TypeAdapter(X).json_schema())]`. `X | SkipJsonSchema[None]` turns the field into a real union, so one bad value gives two errors and the error location gains the member tag (`completed.bool`), which breaks per-field error messages.
